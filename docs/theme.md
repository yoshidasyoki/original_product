# オリプロテーマ決め
オリプロで制作するアプリのテーマ決めと大まかな仕様・要件を洗い出す。

## 解決したい課題 / 潜在的なニーズ
自分の部署で運用している3Dプリンターの貸出・メンテナンス業務に課題を抱えている。  
具体的には以下のような課題がある。

### 課題①：貸出管理
試作や治具製作用に1台、自部署で3Dプリンターを運用しているのだが、社内での3Dプリンターのニーズが高まってきたことから他部署への貸出も近年行うようになった。  
しかし利用者が増加してきたことで自部署の人が使いたくても使えないという問題が発生、業務に支障が出ることも...。  
→ 自部署の人が優先して使えるような仕組みにしてほしいとのニーズが上がるようになった

当初はoutlook（メールサービス）のスケジュール機能での解決を試みたが、依頼の優先付けが行えず今回の制作に至る。

### 課題②：メンテナンス管理
運用している3Dプリンターは稼働時間等に応じてメンテナンスが必要となるため、点検日や稼働時間をスプレッドシートで記録していた。  
しかし、稼働時間については予約が入るたびに手動で登録しなければならず、単純ながら非常に煩わしい業務であった。  
また繁忙期等で記録をつけ忘れることも多々あり、特に最近はメンテナンス管理がしっかりと行えていないことが課題。  
（メンテナンスに手が回らない結果、使用中に機械が故障して復旧までに1週間以上かかる事例も発生。対策が必要）  

→ メンテナンスの作業自体は簡易だが記録付けが行えていないことにより不安定な運用となってしまっている

## 対象ユーザー
社内のうち3Dプリンターを使用する社員（自部署および開発・設計部門の人）  
※ 利用者は現在は1ヶ月で10人程度、ただし今後増加する可能性あり  

## プロダクトのカテゴリー
業務用アプリ（予約機能＋メンテナンスアシスト機能）

## 提供する価値
このアプリを制作することで以下の価値を提供する
- 自部署の業務を停滞させない
予約に優先度をつけられるようにする（承認制にする感じか？）ことで自部署を優先、空いている時間は他部署の人が利用できるという形とすることで、共存した形での利用法を提供できる。
- メンテナンス管理で時間をとらせない
従来の重荷となっていた記録業務をすべてアプリへ移管、作業員はアプリの通知をもとに交換作業を行う形とすることでメンテナンス管理に要していた業務負荷を大幅低減することができる。

## 価値を実現するための最小限の機能（MVP）
- 予約の承認フロー導入：管理者（自部署内ユーザ）が予約の優先度を設定できるようにする
- 操作性の高いUI：業務の負荷低減を目標に作成するアプリなので使いやすいUI・UXを提供する
- メンテナンス管理の自動化：稼働時間の記録＆定期メンテナンスの通知は実装したいところ

## 既存の代替手段・強合との違い
調べてみたところ、予約システムについては既にパッケージ化されて販売されているものはあった。  
ただし、今回はメンテナンス管理がかなりオリジナルの要件でありこちらを既存のもので実現するのはハードルが高そう。  
（できたとしても新規で自分で作るより機能面で劣る可能性がある。開発工数を見越しても自分で作る方が有利と判断）

## 技術的にこだわりたい・工夫したい点
- 排他制御：重複予約が入るとかなりまずいのでここはしっかりと実装したい
- テスト込みでの実装：最低でもバックエンド側は動作テスト込みで実装してバグ混入を防ぎたい
- CI/CD導入：運用面も見越して余裕があればCI/CDの導入も行いたい（修正が起こる前提で考える導入しておきたい）

## なぜ自分がこれを作るのか？
会社に入って業務用アプリの使いにくさにイライラすることが結構あった。  
UI・UX含めて「使いやすい！」と思ってもらえる業務システムを作りたいという思いが入社のときからずっとあった。  
業務が効率化した！と心から思ってもらえる価値を提供する＝自分がエンジニアを目指す最も大きな原動力なのでそれにマッチしたアプリの制作を目指す。
